# 架构与边界

## 当前运行链路

1. Agent 通过 CLI 或本地 HTTP 调用受控工具。
2. Flask 校验参数、期望版本、布局与幂等 ID，将期望状态/事件写入 SQLite。
3. 可见的 `wander.html` 轮询状态；Three.js 执行导航、姿态过渡及渲染。
4. 执行页面回传身体快照与动作进度；Agent 用 `observe_home` 获得完成/受阻结果。
5. 截图由该可见页面渲染并上传到本地服务，Agent 获取 PNG。

期望状态和实际身体快照分开：HTTP 受理不表示角色已走到/坐下。执行页租约避免多个窗口同时驱动身体，不能用手动删状态绕过。

## 目录

- `house3d/server.py`：本地 HTTP、持久化命令、状态转换。
- `house3d/agent.py` / `tool_schemas.py`：CLI 与 function schemas。
- `layout_update.py` / `furniture_support.py` / `room_geometry.py`：批量预演、承载、房间边界。
- `home_runtime.py` / `home_observation.py`：身体回传、执行者、新鲜度与观察。
- `house3d/web/wander*.js`：生活画布、导航与交互；Canvas 内界面，无 HTML 控制侧栏。
- `house3d/room-presets.json`、`furniture-assets.json`、`wallpapers.json`：模板与可发现目录。
- `house3d/assets/`：本地 GLB/纹理，运行时不访问模型生成网站。
- `modeling/`：少量测试布局与来源声明。完整 Blender 工程/制作历史仅在本机相邻 `dafeiyu-home` 保留。
- 此轻量仓库不包含上游 2D 原型与历史模型对比页；本机完整工程仍保留。

## 运行和安全

服务默认监听 `127.0.0.1:19130`，当前没有可用于公网的登录、用户隔离或远程认证。请求有本地 host/origin 检查，但这不替代认证；不要直接反向代理公开。未经独立设计，不接 DSH、QQ、桌面聊天或业务服务。

SQLite 位于 `house3d/data/house.sqlite`，包含状态、命令/事件、身体快照及截图，默认忽略上传。备份用 SQLite backup API；恢复前正常停服务，不在运行中替换文件。已导出的模型与源代码在仓库中，运行时数据不属于发行内容。

没有可见执行页时，只能维护持久状态；不会在服务器常驻一个 3D 渲染器。自主走跑、交互过渡及截图仍依赖前台页面，不保证后台标签页、休眠/容器重建后的实时性，也未完成无头服务端渲染或服务器/WSL 性能实测。

## 图形与内容约束

浏览器 WebGL / Three.js，GLB/glTF 资产，单位米。房间尺寸、资产碰撞范围、安全承载面和交互点由目录明确声明。碰撞和可见性使用近似边界，不是通用刚体/布料仿真。

人物保持已经验收的静态外观、专用骨骼/权重修复和动作。人物使用无光照底色，避免贴图与写实光照叠加灰脸；房间和家具使用独立灯光/阴影，因此人物不会像物理材质一样完全随昼夜变暗。当前没有通用换装系统。

目录中的“家具可显示”与“人物能正确坐卧”分开。新资产默认不凭类别继承接触动作，必须逐件验证。未来社区内容包需要另外定义导入、许可、大小/资源预算和校验，不把当前目录伪装成已完成的插件生态。
